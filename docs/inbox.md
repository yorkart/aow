# Inbox

Inbox 是浮动工作区中的全局需求列表；手机端可从顶部 Inbox 入口打开。

点击底部固定的「添加需求」，直接在列表中新建 Markdown 输入框，默认填入 `## `，光标放在末尾，方便直接输入标题；无需先配置项目、标签或 Agent。第一行用作条目的预览标题，数据中不拆分标题和正文。新增和编辑均自动保存，不显示保存、取消按钮：输入立即保留本地草稿，短暂停顿（350ms）后写入服务端；保存过程中可继续输入，后续修改按顺序写入。底部按钮采用紧凑高度与较小外层间距。

双击已有需求的内容即可就地编辑（键盘聚焦内容后可按 Enter 或 F2），输入区复用系统 Monaco 编辑器，提供 Markdown 语法高亮；隐藏行号、折叠栏、缩略图和当前行背景，自动换行并随内容调整高度。编辑时与原内容左右对齐，操作栏高度保持不变。点击条目外部或按 `⌘ / Ctrl + Enter`、`Escape`，立即退出编辑、恢复 Markdown 渲染，并写入最后一轮修改。忽略全部空白字符（包括中间的空格和换行）后，内容为空或只含一个或多个 `#`，视为没有输入：编辑期间仅保留本地草稿，退出编辑时移除条目；已经自动保存的条目也会同步删除，尚在保存中的条目会在确认保存结果后删除。移除失败保留待删除状态供重试，版本冲突仍需用户选择。其他未写入成功的内容保存在当前浏览器中，刷新或重新打开后可继续编辑。

每条需求可绑定或解除绑定项目，并从条目左下角的标签选择器选择多个标签。默认提供 TODO、InProgress、Review、Done；顶部「配置标签」可新增、重命名、调整颜色或删除标签。删除标签会同时移除需求上的对应标记。标签仅用于整理，不自动触发执行或状态流转。

编辑时仍可调整项目和标签，并自动保存：项目单选，选中即收起；标签多选，可连续勾选。操作条目内的项目、标签菜单不会结束编辑；菜单内的 `Escape` 只收起菜单。条目选择器与顶部项目、标签筛选使用统一的下拉菜单样式；项目筛选单选，标签筛选多选（匹配任一标签）。

顶部支持文本搜索、项目筛选（含未绑定）及标签筛选。多个标签按 OR 匹配，再与项目和文本条件组合。拖动左侧手柄可改变顺序，触屏也可使用；聚焦手柄后可用上下方向键移动。筛选时移动某条需求不会重新排列未移动条目的相对顺序。

需求绑定有效项目后，点击执行图标直接展开 Agent 菜单，点击可用的 Agent 即开始执行；所有 Agent 都会列出，不可用或暂不支持自动提交的项会标明原因。执行使用项目的注册工作目录，将完整的原始 Markdown 作为初始输入，创建一个新的交互 Agent 终端。当前自动提交能力支持 Codex、Trae CLI、Hermes、Pi 及对应的自定义配置。执行状态「已交给 Agent」表示初始输入已提交，不代表需求已完成；标签由用户自行维护。可通过条目中的「打开终端」继续查看或对话。

执行使用独立请求标识去重。重复提交同一执行请求不会再创建终端；同一需求正在启动 Agent 时，新的执行请求会被拒绝。服务重启后，未确认的启动记录标记为待确认，不自动重放需求。再次执行前应先检查已有终端。删除需求不会停止或删除已经创建的终端。

提交给 Agent 的任务以严格 XML `<aow-inbox>` 上下文开头，固定包含 `requirement`（当前需求 ID）、`execution`（本次执行 ID）和 `description` 三个子节点。描述使用英文说明任务来自 AoW Inbox，以及可通过 `aow-cli inbox` 获取需求和评论、更新需求、追加评论。原始需求和补充 prompt 在 XML 外保留原文；执行记录保存包含 XML 的实际提交内容。完整任务（含上下文）最多 128 KiB。Agent 通过继承的 `AOW_STATE_DIR` 访问发起任务的服务实例。

有评论的需求会在执行图标前显示评论图标。点击后直接在该需求下方展开评论，再次点击收起；没有评论时隐藏图标。评论按追加顺序逐条渲染 Markdown，显示作者和时间，只读展示，不提供编辑或删除操作。展开后，新评论通过工作区实时事件刷新。

## 存储与并发

- Inbox 保存在当前配置仓库的 `CONFIG_DIR/inbox/`，通过现有配置仓库机制写入并提交 Git。旧 `inbox.json` 已废弃，不读取、不迁移。
- `inbox/labels.json` 保存标签定义，以及列表版本、条目顺序和录入去重信息。
- 每条需求位于 `inbox/requirements/active/<需求 ID>/`，目录中固定两个文件：`requirement.json` 保存原始 Markdown、可选项目 ID、标签 ID、版本和时间戳；`comments.jsonl` 保存评论，没有评论时为空文件。
- 评论只追加，每行一个 JSON 对象，正文中的换行以 `\n` 转义。每条评论保存 `id`、`author`（`type` 为 `human` 或 `ai`，以及 `name`）、`created_at` 和 `content`；通过 API 追加的评论还保存 `request_key`，相同请求重试不会重复追加，使用同一标识修改内容会返回 409。评论追加不改变需求版本，也不重写已有评论。
- 删除需求时，将整个目录移动到 `inbox/requirements/deleted/<需求 ID>/`，两个文件及全部评论保留，列表不再显示该需求。删除不会物理清除内容。
- 执行输入快照及终端关联保存在本机 `STATE_DIR/inbox/CONFIG_ID/executions.json`，不提交到配置仓库，配置之间相互隔离。
- 录入与执行请求都有独立去重标识。编辑和删除检查条目版本，排序和标签配置检查列表版本；并发冲突返回 409，前端保留编辑草稿并允许用户检查新版本后再保存。
- 自动保存失败会显示错误并保留本地草稿，可重试；继续输入或网络恢复时也会再次尝试。首次录入重试使用相同的请求标识与原始内容，确认创建成功后再更新后续输入，避免重复创建。中文输入法组词期间不会写入未完成的内容。
- 工作区实时事件通知其他页面刷新；Agent 启动期间额外查询状态。已启动服务不会自动导入磁盘外部编辑，修改配置文件后需要重启服务。
- 新实现不读取或迁移旧 Tasks 数据。

## API

所有接口沿用 Web 登录认证及部署路径前缀。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/inbox` | 读取有序需求、标签、列表版本、`comment_counts`（需求 ID 到评论数量的映射）及每条需求最近一次启动记录 |
| `POST /api/inbox/items` | 录入需求：`markdown`、`request_key`；服务端分配资源 ID |
| `GET /api/inbox/items/{id}` | 读取单个需求及当前版本 |
| `PUT /api/inbox/items/{id}` | 更新需求：`expected_revision`、`markdown`、`project_id`（可为 null）、`label_ids` |
| `DELETE /api/inbox/items/{id}` | 将需求目录移到 `deleted/`，JSON body 携带 `expected_revision` |
| `GET /api/inbox/items/{id}/comments` | 按追加顺序读取评论数组 |
| `POST /api/inbox/items/{id}/comments` | 追加评论：`request_key`、`author`（`type`、`name`）、`content`；服务端分配评论 ID 和创建时间 |
| `PUT /api/inbox/order` | 移动一条需求：`expected_revision`、`item_id`、`before_id`（null 表示末尾） |
| `PUT /api/inbox/labels` | 替换标签定义：`expected_revision`、`labels`（`id`、`name`、`color`） |
| `POST /api/inbox/items/{id}/execute` | 启动执行：`expected_revision`、`request_key`、`agent`，返回 202 和启动记录 |

Markdown 上限为 128 KiB；标签最多 64 个，名称不超过 40 字且不重名，颜色为 `#RRGGBB`。

评论正文上限为 128 KiB，作者名称不能为空且最多 80 字。不提供评论更新或删除接口；被删除需求的评论接口返回 404。

本机 CLI 通过私有 Unix socket 使用同一组处理逻辑，路径前缀为 `/v1/inbox`，无需浏览器登录或 terminald。支持列出、获取、创建、更新和删除需求，以及读取、追加评论，详见 [AoW CLI 使用](aow-cli.md#inbox-需求与评论)。所有修改统一触发网页刷新。
