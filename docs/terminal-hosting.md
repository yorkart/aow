# Agent Terminal 托管

先在 Automation 中创建手动任务，将工作区方式设为「动态工作区 → 动态指定」，再点击 Agent 窗口标题栏右侧的「Autopilot」，配置「最多自动输入次数」（默认 3，必须为正整数），选择当前项目的任务。列表仅显示动态指定工作区的手动任务。选择后立即开启托管；控制台进入旁观状态，可查看、选择和复制输出。

「开启托管后立即执行一次」默认勾选：成功取得控制权后立即运行所选手动任务，不等待当前任务结束，也不检测 Agent 是否空闲。取消勾选则只等待启用后的下一次完成事件。开启接口 `PUT /api/terminals/{tab_id}/panes/{pane_id}/hosting` 的布尔参数 `run_on_enable` 省略时默认为 `true`，传 `false` 保留等待行为。

「动态指定」仅手动任务可选，在调度任务和 Inbox 的工作区配置中显示为禁用。普通手动执行时必须填写当前项目 Worktree 或其子目录的绝对路径；Autopilot 自动提供被托管 Agent 的实际工作目录。「动态工作区 → 临时工作区」仍创建空目录，不能用于 Autopilot。已有任务需改为「动态指定」后再绑定，系统不会自动改写其工作区配置。

托管状态沿用控制台现有的「旁观中 / 接管」位置，显示任务名称和当前进度。点击「接管」解除托管并恢复人工输入。已经启动的 Review run 会保留执行记录，其迟到结果不会再输入终端。

## 执行流程

1. 后端确认当前 Agent 的进程和会话身份，在开启托管时订阅后续任务完成事件。
2. 勾选立即执行时，成功取得托管控制权后主动创建首次 Review；否则等该实例的新完成事件后创建。开启前已完成的任务不补触发，也不读取历史重建轮次。首次主动 Review 不伪造原 Agent 的完成事件或页面、IM 完成通知。
3. Autopilot 为本次运行提供原 Agent 的实际工作目录，包括未提交的变更；手动任务模板仍保持「动态指定」，不保存固定目录。
4. Runner 在发布运行完成状态前保存本次执行结果，Autopilot 读取该 run 已保存的最终回复。若最后一个非空行单独输出 `[AOW_HOSTING_DONE]`，则审查通过，结束托管，本次结论不再输入终端。
5. 未匹配结束标记且未达到上限时，原样将结论提交到原终端，并发送 Enter；成功提交后自动输入次数加一。空结果或执行失败按异常处理。
6. 等待原 Agent 下一轮完成后再次审查。达到上限后仍允许最后一次审查：通过则正常结束，否则停止托管，保留待处理结论的执行记录，不再自动输入。

首次 Review 与后续 Review 共用结果收集、结束标记、失败处理、反馈输入和次数上限逻辑，Review 本身不增加自动输入次数。例如上限为 3 时，最多自动输入 3 次，最多执行 4 次审查。Review run 的 `completed` 仅表示执行正常退出；结束标记才表示审查通过。后端只匹配最终回复最后一个非空行的完整标记，句子、引用、代码块中的标记以及自然语言“通过”均不会触发结束。

流程由后端驱动，关闭浏览器不会停止托管，与任务完成通知开关无关。同一轮只触发一次 Review，同一实例的反馈提交与人工接管串行执行。次数和结束状态持久化，刷新或重启不会重置。审查通过或达到上限后控制台继续旁观，显示结束原因、已用次数和本次执行入口；点击「接管」恢复人工输入。

Autopilot 直接订阅现有任务完成检测器产生的事件，与页面和 IM 通知共用事件来源，不另外扫描原终端的会话内容。内部订阅不受通知开关影响。Automation 负责在运行结束时收集并保存结果，Agent 适配层复用原生完成解析器提取最终回复；Claude 未写入原生结束事件时，以进程成功退出为结束依据。Autopilot 只负责触发审查、检查结束标记和次数、提交反馈。

## 手动任务上下文

无需配置变量也能使用。结束标记由系统固定，无需配置。Runner 在替换任务变量后注入以下说明，保留手动任务原有的执行和输出要求：

```text
你正在执行一次审查任务，请遵循任务原有的执行和输出要求。审查通过时，在最终输出的最后另起一行，单独追加标记：[AOW_HOSTING_DONE]。

审查任务：
<变量替换后的手动任务描述>
```

Autopilot 运行仅注入上述说明和任务描述，所需的本轮信息通过任务显式配置的变量提供。Automation Runner 在进程成功退出后复用 Agent 原生完成解析器收集最终回复，保存到本次运行的通用 `result.json`，再发布运行完成状态。Autopilot 只读取这份结果，不重新读取会话；结果不可用时显示收集错误。普通手动执行不注入这段说明，保存的任务模板保持原样。

如果手动任务配置了变量，首版自动填充以下名称：

| 变量 | 值 |
| --- | --- |
| `workspace` | 原 Agent 的实际工作目录 |
| `session_id` | 原 Agent 会话 ID |
| `turn_id` | 本轮任务 ID |
| `conclusion` | 原 Agent 的本轮最终回复 |

开启后立即执行的首次 Review 没有对应的原 Agent 完成事件：`workspace` 和 `session_id` 正常提供，`turn_id` 和 `conclusion` 使用现有缺省值「（无）」。后续由完成事件触发的 Review 使用该事件的值；缺失或空白值同样替换为「（无）」。

其他必填变量会在开启托管时提示不支持。修改已绑定的手动任务后，需要接管并重新选择任务；已经提交的 run 使用提交时的配置。

## 异常与恢复

执行失败、并发限制、无法提取结论或终端身份变化时，托管暂停，在「接管」附近显示警告。已关联 run 的错误提供「查看本次执行」，打开该 run 的执行 Tab。

macOS 调度优先使用当前账户的 GUI 域；没有桌面登录会话时使用同账户的用户域，并允许 Background 会话类型。审查任务显式提交到该域，即使 AoW 作为 LaunchDaemon 运行也不需要授予服务账户系统服务管理权限。旧版本若报 `Could not print domain: 125`，更新服务后点击「接管」并重新开启 Autopilot；失败的运行记录保留，不自动重放。

每次新开启托管只主动触发一次，刷新页面或 AoW 重启不会重放首次 Review。AoW 重启后恢复等待时只订阅后续事件，不补查停机期间的完成记录；已经持久化的审查 run 继续追踪，不重新派发。若重启或超时发生在反馈提交期间，送达状态可能不确定，此时暂停并提示人工接管确认，不自动重发。终端重建不继承旧实例的托管。

当前需能唯一定位原 Agent 会话。Codex / TraeCode 的标题匹配存在歧义时会拒绝开启，可先将会话改为唯一标题再重试。Review 使用新会话；如果该会话被手动续接，后端不会把后续任务的回复当成本次 Review 结论。
